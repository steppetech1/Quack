# deploy/ — выкатка Quack на сервер

Это инструкция владельцу (ТЗ Фазы 4 WP9, Д-§13 P0). Скрипты сдаются готовыми; шаги с оплатой, DNS и
секретами делает владелец.

## Что здесь

| Файл | Назначение |
| :-- | :-- |
| `Caddyfile` | TLS, редирект 80 → 443, прокси на `api`. Наружу только `/healthz`, `/auth/*`, `/v1/*`; остальное, в том числе `/health/*` и `/internal/*`, отвечает 404 (Д-§3.1, Д-§9.1) |
| `static/viz/` | Закреплённые D3 7.9.0, Plotly 2.35.2, KaTeX 0.16.11 для страниц визуализаций; Caddy отдаёт их как `/static/viz/*`, имена и пути — `VIZ_LIBRARIES` в `compose.yaml`; `SHA256SUMS` сверяется тестом (WP9.2, D-C-218) |
| `env.example` | Имена переменных `.env` без значений |
| `setup-server.sh` | Первичная настройка чистого Ubuntu 24.04 (Д-§10) |
| `deploy.sh <sha>` | Выкатка и откат по Д-§6.1 и Д-§6.3 |

## Порядок первого запуска

1. **Сервер.** Contabo Cloud VPS 6, Ubuntu 24.04, EU. Перед оплатой сверить тариф (Д-§14.2).
2. **Файрвол в панели провайдера:** входящие 22, 80, 443. Скрипт настраивает ещё и `ufw`.
3. **DNS в Cloudflare** (серое облако): `api` A на IPv4 сервера, TTL 300. AAAA для `api` не ставить (Д-§3.1). Остальные записи — по таблице Д-§3.1.
4. **Настройка сервера** под root:
   ```bash
   ADMIN_SSH_PUBKEY='ssh-ed25519 …' DEPLOY_SSH_PUBKEY='ssh-ed25519 …' bash setup-server.sh
   ```
   До закрытия сессии проверить из другого терминала `ssh admin@<сервер>`: вход под root и по паролю отключён.
5. **GitHub Environment `production`:** секреты `DEPLOY_HOST`, `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS` (`ssh-keyscan -t ed25519 <сервер>`) и секреты из `env.example`. Job выкатки — отдельный пакет (WP9.3/9.4), он рендерит `/srv/quack/.env` с правами 600.
6. **Файлы на сервере.** В `/srv/quack` должны лежать `compose.yaml`, `deploy/` и `.env`.
7. **Образы.** CI (job `publish` в `ci.yml`) на каждый push в `main` и `phase-4` после зелёных проверок публикует `ghcr.io/<owner>/quack-backend` и `quack-compute` с тегами `<7 символов sha>` и `<ветка>`. После первой публикации пакеты приватные: в GitHub → Packages → каждый пакет → Package settings → Change visibility → Public, затем проверить `docker pull` на сервере без входа (Д-§5.1). В `deploy.sh` передаётся тот же короткий sha.
8. **Первая выкатка** (баз ещё нет, дампить нечего):
   ```bash
   ALLOW_NO_DUMP=1 ./deploy/deploy.sh <sha>
   ```
   Дальше `ALLOW_NO_DUMP` не нужен: перед миграцией скрипт делает дамп (`ops backup now`).

**Схема и процессы (WP1.3, D-C-160).** Сервис `migrate` (`ops migrate`) запускает `dbmate up` на `/app/db/migrations` образа; `api`, `projector` и `workers` ждут его завершения и стартуют на процессах Фазы 4 (переключателя процессов Фаз 3 и 4 больше нет: D-A-223…225). Стенд с базой Фаз 1-3 (Alembic) не мигрируется: `ops migrate` видит `public.alembic_version`, отказывает с кодом 1, выкатка останавливается, сервисы остаются на старой версии. Чистый старт: остановить стек и пересоздать базу (`docker compose down`, `docker volume rm quack_postgres-data`), затем `ALLOW_NO_DUMP=1 ./deploy/deploy.sh <sha>`. `ops status` читает схему Фазы 4 (D-C-181): проверка выкатки после `migrate` проходит.

Журнал выкаток — `/srv/quack/deploy.log`, текущий релиз — `/srv/quack/release.env`.

## Бэкап

`ops backup` (сервис `backup`, профиль `backup`: `docker compose up` его не стартует). Таймер `quack-backup.timer` ставит `setup-server.sh`, раз в 6 часов. Поток: `pg_dump -Fc --compress=zstd` → `age` (публичный ключ `BACKUP_AGE_PUBLIC_KEY`) → бакет `quack-backups/dumps/`; две последние копии без шифрования лежат в `/srv/quack/backups` (700/600). После успеха — пинг `HEARTBEAT_BACKUP_URL`, после неудачи — вебхук `ALERT_WEBHOOK_URL`. Приватный ключ `age` на сервере не хранится. Дамп читает базу ролью `quack_reader`: её создаёт `ops db-roles`, `deploy.sh` запускает его перед дампом и миграцией.

Пробная проверка без R2: `BACKUP_S3_ENDPOINT=file:///путь` пишет в каталог.

## Тревоги

`ops alerts` (сервис `alerts`, профиль `alerts`) раз в 5 минут проверяет условия Д-§9.3: `/healthz`, остановленные потоки проектора, возраст последнего дампа (интервал бэкапа + 30 минут), состояние контейнеров и диск (75% и 90%), отставание проектора, самую старую задачу в очереди, долю неуспешных задач, флаг давления и размыкатель моделей. Сообщения идут вебхуком `ALERT_WEBHOOK_URL` (формат `ALERT_WEBHOOK_FORMAT`), после каждой проверки пингуется `HEARTBEAT_ALERTS_URL`: если сервер или таймер умерли, тревогу поднимает внешний сервис.

Каждое условие объявляется, когда продержалось своё время (например, `/healthz` — 5 минут), и повторяется не чаще раза в час. Данные о контейнерах и диске пишет таймер хоста `quack-host-state` в `/run/quack/state.json` (у контейнера `alerts` нет сокета Docker). Таймеры `quack-alerts` и `quack-host-state` ставит `setup-server.sh`. Пока не настроен бэкап, тревога «нет успешного бэкапа» будет повторяться раз в час: это ожидаемо.

## Откат

`./deploy/deploy.sh <предыдущий sha>`. Скрипт видит, что этот SHA уже выкатывался, пропускает дамп и миграции и спрашивает `ops can-rollback`. Откат запрещён, если в журнале появились новые типы событий или сменилась `rules@N` (Д-§6.3): тогда только исправление вперёд. После ручного отката со сменой правил: `ops rebuild --stale-rules`.

Проверка после выкатки не прошла — автоматический откат делается только для релиза без новых событий, без смены `rules@N` и без новых миграций.

## Что пока не готово

- **Тревоги по расходу в долларах** (`team_daily_alert_usd`, нужна таблица `ops.llm_usage`, WP10.4), по объектам `quack-deletions` без строки в журнале (WP25) и по дате оплаты Contabo.
- **Перевод `api`, `workers`, `projector` и `migrate` на роли `quack_app` и `quack_migrator`**: схема уже идёт через dbmate, но SQLAlchemy-код Фазы 3 ещё не снят (WP1.3, шаг 5, поток A), поэтому сервисы пока работают под `quack` (D-C-160).
- **CORS** API (`cors_origins` уже есть в конфиге, подключение к приложению — отдельный пакет).

## Локальная проверка

Caddyfile:

```bash
docker run --rm -v "$PWD/deploy/Caddyfile:/etc/caddy/Caddyfile:ro" caddy:2.10 \
  caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
```

Весь стек с локальным сертификатом: в `.env` `API_DOMAIN=localhost`, затем `docker compose up`; `https://localhost/healthz` отвечает 200, `https://localhost/health/ready` — 404.

## Только `compose.yaml` на сервере

`compose.override.yaml` лежит в репозитории для локальной работы: он публикует базы и API на `127.0.0.1` и подключает их к сети с интернетом. Docker Compose читает его автоматически, поэтому на сервере всегда задавайте `COMPOSE_FILE=compose.yaml` (`deploy.sh` и таймер бэкапа делают это сами). Для ручных команд:

```bash
export COMPOSE_FILE=compose.yaml
docker compose --env-file .env --env-file release.env ps
```

Проверка: у `postgres`, `neo4j`, `redis` и `api` в колонке PORTS ничего нет, 80 и 443 только у `caddy`.

## Восстановление

Порядок — Д-§8.3. Команды `ops` запускаются так: `docker compose run --rm migrate ops <команда>` для тех, что читают только Postgres и Neo4j (`restore-check`, `resume`), и `docker compose run --rm --no-deps workers ops <команда>` для тех, что ходят в хранилища (`replay-deletions`, `orphan-objects`): у `workers` есть ключи `quack-learners` и `quack-deletions`.

- `ops replay-deletions --since <время дампа>` (шаг 5) повторяет все записи журнала `quack-deletions` новее дампа; повтор идемпотентен. Печатает `{"replayed": N}`.
- `ops restore-check` сравнивает у каждого ученика `projectedSeq` в Neo4j с `seq` в `core.learners`. Если граф опережает журнал, команда печатает список учеников и завершается кодом 1: тогда `ops rebuild --all`. Отстающий граф проверку не ломает, проектор его догонит. Без пройденной проверки остальные сервисы после восстановления не запускаются.
- `ops orphan-objects --since <время дампа> [--apply]` (последний шаг) ищет в `quack-learners` объекты новее дампа, на которые нет ссылок в Postgres (материалы, страницы, выгрузки, холсты, ключи в событиях и версиях артефактов). Без `--apply` только печатает отчёт `{checked, orphans, deleted: 0, dry_run: true}` и ничего не удаляет; удаляет лишь с явным `--apply`. Сначала запустите без флага, просмотрите список, затем повторите с `--apply`.
- `ops resume --learner <id>` снимает остановку потока проектора после исправления причины (Д-§8.7); `ops rebuild --all --concurrency N` пересобирает графы по N учеников сразу (по умолчанию `rebuild_concurrency`).

## Выкатка из GitHub Actions

`.github/workflows/deploy.yml` (Д-§6.1): по SSH заходит на сервер (`DEPLOY_HOST`, `DEPLOY_SSH_KEY`, проверка ключа хоста по `DEPLOY_KNOWN_HOSTS`, `StrictHostKeyChecking yes`), собирает `/srv/quack/.env` из секретов и переменных окружения `production` по списку имён из `deploy/env.example` (`deploy/render-env.sh`), ставит его (права 600), переключает `/srv/quack` на выкатываемый коммит и запускает `deploy.sh <sha7>`. Одновременно идёт не больше одной выкатки (`concurrency: deploy`). `DEPLOY_FREEZE = true` (переменная репозитория) пропускает выкатку на окно демо.

Запускается двумя способами:
- автоматически после `publish` на push в `main`, если в репозитории задана переменная `DEPLOY_ENABLED = true` (её ставят только в прод-репозитории);
- вручную: Actions → deploy → Run workflow. Поле `sha`: полный sha коммита (40 символов), пустое значит голову выбранной ветки. Этим же запускается откат: укажите sha предыдущего релиза.

**Сухой прогон** (`dry_run`, по умолчанию включён при ручном запуске): ничего не меняет на сервере, а в сводке запуска показывает **имена** ключей, которые отличаются между `.env` на сервере и тем, что собрано из GitHub (`added`, `changed`, `removed`). Значения нигде не печатаются. Первый запуск всегда делайте сухим: пароли баз в GitHub должны совпадать с теми, с которыми создана база, иначе в `changed:` окажется `POSTGRES_PASSWORD` или `*_DB_PASSWORD`, и выкатывать нельзя, пока не выясните причину.

Сборка `.env` отказывается работать, если пусто что-то обязательное (`QUACK_REGISTRY`, пароли баз, `META_API_KEY`), осталась заглушка `<…>` или в значении есть перенос строки.

## Таблица цен моделей (`LLM_PRICES`)

В `ENV=prod` процессы `api` и `workers` не стартуют без таблицы цен (Т-§11.4, WP10.4): значения даёт владелец, в коде их нет. Это переменная `LLM_PRICES` окружения `production` (несекретная), JSON вида `{"<модель>": {"input": …, "cached_input": …, "output": …}}`, цены в долларах за 1 млн токенов. Ключи должны совпадать с именами моделей из таблицы ролей (`muse-wonder-1.0`, `muse-spark-1.3`). Пока она пуста, сборка `.env` в job выкатки отказывается работать, а сервер остаётся на прежнем релизе.
