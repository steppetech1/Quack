# Фронт и бэк: что подключено

Состояние на 2026-11-01.

## Как запустить

Фронт работает в одном из двух режимов. Режим выбирается при сборке переменной окружения в `frontend/.env.local`:

- `NEXT_PUBLIC_QUACK_API=1` — данные идут с бэка;
- без неё — моки из `lib/mock/`, как раньше. Это удобно для работы над дизайном.

Шаблон лежит в `.env.example`. После изменения `.env.local` dev-сервер надо перезапустить.

Бэк берётся из `main`: там весь бэкенд фазы 3. Удобнее всего поднять его через compose из корня репозитория.

1. Рядом с `compose.yaml` создай `.env`. Имена переменных — в `backend/.env.example`, обязательны `POSTGRES_PASSWORD`, `NEO4J_PASSWORD` и `JWT_SECRET`.
2. **Без живого ключа** — подменный сервер Meta (`meta-mock`). Он отвечает по схемам и отдаёт предмет из трёх тем с навыками, так что работает весь путь: структура, граф, практика, сессия. Добавь в `.env`:

   ```bash
   META_API_KEY=stand
   META_API_BASE_URL=http://meta-mock:8080
   META_MOCK_LATENCY=zero
   ```

   `META_MOCK_LATENCY=zero` убирает задержку ответа. По умолчанию задержка как у живой модели, у учителя это около 14 с.
3. Запуск:

   ```bash
   docker compose --profile loadtest up -d --build
   ```

   `compose.override.yaml` открывает API на `127.0.0.1:8000`. Миграции, проектор и воркеры поднимаются сами. Воркеры обязательны: они строят граф, шпаргалки и итоги сессий.

   **С живым ключом** профиль `loadtest` не нужен: `META_API_KEY` — настоящий ключ, `META_API_BASE_URL` не задавай.
4. Фронт:

   ```bash
   npm run dev
   ```

Браузер обращается только к фронту. Next.js проксирует `/api/*` на `QUACK_API_URL` (по умолчанию `http://localhost:8000`, см. `next.config.ts`), поэтому CORS на бэке не нужен.

Без `META_API_KEY` бэк работает в упрощённом режиме. Предложение тем даёт по одной теме на каждый пункт фокуса, без навыков, поэтому практика по ним не открывается. Учитель отвечает заглушкой.

## Как устроено во фронте

- `lib/api/client.ts` — запросы, токен (`localStorage`, ключ `quack.token`), ошибки, SSE через `fetch`. `post`, `patch`, `del` и `sse` типизированы по контракту: путь вызова сопоставляется с шаблоном пути из схемы, тело и ответ берутся из этой операции. Неверное тело — ошибка компиляции, а не 422 на бэке.
- `lib/api/schema.d.ts` — типы, сгенерированные из `lib/api/openapi.json`. Снимок `openapi.json` скопирован из `backend/openapi.json` в `main`. После изменений API скопируй его заново и выполни `npm run api:types`. Скрипт запускается с `--default-non-nullable false`, поэтому поля запроса со значением по умолчанию на бэке (`mode`, `kind`) остаются необязательными.
- `lib/api/adapters.ts` — переводит ответы бэка в типы, на которых построен интерфейс (`lib/mock/types.ts`).
- `lib/api/data.tsx` — `DataProvider`: проверка входа, профиль и настройки, список предметов, графы, активная сессия, живые обновления (`appliedSeq`). На моках отдаёт моки.
- `components/quack/live/*` — экраны на данных бэка. Маршруты выбирают живой экран или моковый по `API_MODE`.

## Что подключено

| Экран | Эндпоинты |
|---|---|
| Вход, регистрация, выход | `POST /v1/auth/login`, `POST /v1/auth/register`, `GET /v1/auth/me` |
| Левая панель, вкладка «Предметы» в настройках | `GET /v1/domains` |
| Граф предмета | `GET /v1/domains/{id}/graph` |
| Новый предмет | `POST /v1/domains`, `POST …/structure/propose` |
| Темы предмета: пропустить, добавить, подтвердить, архив | `POST …/structure/confirm`, `PATCH …/structure`, `PATCH …/topics/{id}/status`, `POST …/archive` |
| Диагностика | `POST …/diagnostic/start`, `…/answer`, `…/finish` |
| Страница темы: навыки, заблуждения, заметки, шпаргалка | `GET /v1/topics/{id}`, `GET /v1/artifacts?topic_id=`, `GET /v1/topics/{id}/cheatsheet`, `POST …/cheatsheet/refresh` (тело `{domain_id}`) |
| Сессия: история, ответ учителя потоком, «учитель думает» (`status`), задачи, присутствие, конец | `POST /v1/sessions`, `GET /v1/sessions/{id}`, `POST …/turns` (SSE), `POST …/heartbeat`, `POST …/finish`, `GET /v1/sessions/active` |
| Итог сессии | данные из `finish` |
| Практика | `POST /v1/sessions` (practice), `POST …/tasks/next`, `…/hint`, `…/submit` |
| Заметки и шпаргалки, поиск, выгрузка | `GET /v1/artifacts`, `GET /v1/artifacts/search`, `GET /v1/domains/{id}/export` |
| Заметка | `POST /v1/artifacts/notes`, `PATCH …/{id}`, `DELETE …/{id}` |
| Удаление аккаунта | `DELETE /v1/learner` (без тела) |
| Настройки «Общие» и «Язык»: имя, обращение, курс, язык ответов | `PATCH /v1/learner/preferences`, чтение из `GET /v1/auth/me` |
| Живые обновления: список предметов, графы на экране, страница темы | `GET /v1/learner/stream` (SSE `projection_advanced`, данные — обычными GET) |

Не подключено: `GET /v1/sessions/{id}/events`. Бэк хранит настройки, но учитель их пока не читает: обращение и язык ответов на его поведение не влияют.

## Чего нет на бэке (во фронте остаётся на моках или скрыто)

- **Главы (хабы) и дедлайны.** Все темы предмета показаны в одной главе «Все темы». Страница главы работает только на моках.
- **История сессий.** Есть только активная сессия, поэтому в правой панели не больше одной записи.
- «Сегодня», канвасы, карточки для повторения, материалы (загрузка лекций), готовность к дедлайну.
- Скиллы пользователя (свои промпты) хранятся в `localStorage`. На бэке «skill» значит другое: навык внутри темы.

## Состояния тем

У бэка пять состояний темы, в дизайне четыре:

- `solid` → «решаешь сам»;
- `in_progress` и `rusty` → «пора повторить»;
- `available` и `locked` → «ещё не изучал».

«Путаешь» с бэка пока не выставляется: заблуждения видны на странице темы. Пропущенные и архивные темы на граф не попадают.
