# Реестр маршрутов для контрактных тестов (D-C-147)

Каждый поток описывает свои маршруты в **своём** файле этого пакета: `a.py`, `b.py`, `c.py`.
Общие тесты ничего не перечисляют, а собирают потоки:

- `T-A1` (`tests/test_app_assembly.py`): смонтированные маршруты = объединение `routes` и
  `other_routes` всех потоков; роутеры из `routers` объявляют только смонтированное.
- `T-E2` (`tests/e2e/test_isolation_and_idempotency.py`): каждый смонтированный изменяющий
  `/v1`-маршрут либо с `no_key` (с причиной), либо в обходе по возрастанию `stage`. Повтор с тем
  же ключом и телом → тот же ответ, событий не прибавилось; тот же ключ с другим телом → 409.
- `T-E3`: каждый маршрут с `{id}` в пути для чужого ученика → 404; данные владельца не меняются.
- `tests/test_route_registry.py` проверяет сам реестр (без инфраструктуры).

## Как добавить маршрут (файл своего потока, 3–5 строк)

Читающий маршрут (GET), публичный вход, здоровье — одна строка в `other_routes`:

```text
other_routes=frozenset({("GET", "/v1/domains/{domain_id}/today")}),
```

Изменяющий маршрут с ключом — запись `Route` в `routes` потока:

```text
Route("POST", "/v1/x/{x_id}/do", stage=225, requires=("x_id",),
      body=lambda ids, v: {"name": ["A", "B"][v]}, advance=_x_done),
```

`body(ids, v)` — валидное тело **без** ключа; `v=1` отличается от `v=0` полем, не являющимся
ключом (отсюда 409). Новый id пути — строка в `ids=` потока (`"x_id": NO_ID`); общий код не
правится. Новый роутер — строка `"пакет.модуль:router"` в `routers`.

## Поля `Route`

| Поле | Смысл |
| :-- | :-- |
| `stage` | Место в обходе `T-E2` (глобальное число, по возрастанию). Нужно всем маршрутам без `no_key`. Ставь число между шагами, чьи id тебе нужны: 10–120 вход ученика (домен, структура, диагностика), 130–180 сессия, 190–270 конспект, карточки, холст, 280 спор, 290 завершение сессии, 300 архив домена |
| `order` | Порядок внутри одного `stage` (по умолчанию 0) |
| `body` | Фабрика тела `(ids, variant) -> dict`. Нужна, если у маршрута есть `{id}` или ключ; без неё — только `no_key` маршрут без `{id}` в пути |
| `body_key` | Как ключ попадает в тело: `"text"` (по умолчанию), `"uuid"` (ключ — UUID, ТЗ Ф4 WP13.1), `"none"` (модель тела не имеет ключа) |
| `no_key` | **Причина** (правило ТЗ), почему в запросе нет `idempotency_key`. Маршрут не входит в обход `T-E2`. Без ссылки на ТЗ/решение не принимается: ключ — закон 5 |
| `no_other_body` | **Причина**, почему «тот же ключ, другое тело» невозможно (в теле нет других полей). Без причины не ставится |
| `files` | Мультипарт-маршрут: файлы валидного запроса `{"file": (имя, байты, тип)}`. Только вместе с `no_key` |
| `requires` | Id, которые обход должен создать до шага; иначе тест падает с понятным сообщением (порядок `stage` нарушен). Только те id, чьё настоящее значение не равно заглушке |
| `path_ids` | Если параметр пути берётся из другого id: `{"session_id": "action_session_id"}` |
| `restore` | Id, возвращаемые к значениям после входа ученика перед шагом (`("domain_id", "topic_id")`) |
| `prepare` | `async (system, learner, ids) -> ids` до шага: завести то, что нужно шагу |
| `advance` | `async (system, learner, ids, payload) -> ids` после шага: взять из ответа id для следующих шагов |

`Stream.isolation` — функции `(system, learner, ids) -> ids`, которые `T-E3` вызывает один раз,
чтобы завести у ученика A объекты потока (узлы графа, события журнала), на которые ссылаются
пути. Значения id по умолчанию (`NO_ID`, `0`) — «объекта нет»: на них маршрут отвечает 404.
