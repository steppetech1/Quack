# Поток 1: ход учителя, холст, демо — решения

Файл ведёт поток 1 (ветки `feat/dev1-contract-retry-turn`, `feat/dev1-turn-canvas`). Поток 2 пишет свой файл.

## Стык: действие `retry_turn`

Ветка `feat/dev1-contract-retry-turn`, PR «contract: retry_turn action» в `feat/session-plan-graph-and-hardening`.

| Решение | Почему |
| :-- | :-- |
| `RetryTurnAction` (`kind`, `idempotency_key`) в `Action`, в `TURN_ACTION_KINDS`, но не в `ACTION_EVENT_TYPES`. | Событие не пишется: ввод уже в журнале, новый тип события был бы красной линией. Контрактный тест `test_action_kinds_cover_wp13_1` теперь исключает `retry_turn` из сверки с событиями. |
| Вводом считается последнее событие ученика `message.sent`, `answer.submitted`, `element.responded`, `hint.requested`, `solution.requested`, `check.skipped`, `item.flagged_unclear`, на которое нет `turn.committed` с `action_seq` = его `seq`. `answer.submitted` с `causation_seq` (ответ из элемента) вводом не считается: вводом является сам `element.responded`. | Ровно так ход привязывается к действию при записи (`action_seq`). Запрос в `quack/session/retry_turn.py`, `unanswered_input_seq` может взять и поток 2 для `unanswered_seq`. |
| Берётся последний ввод без ответа, даже если после него другие ходы уже есть. | Буква задачи: «последний ввод, на который нет `turn.committed`». Следующий повтор берёт предыдущий сирота, пока их не останется. |
| Если неотвеченных вводов нет, ответ `201 {seq}` с `seq` последнего ввода; если вводов в сессии нет вовсе, `404 NOT_FOUND`. | Двойной клик и повтор запроса безобидны, ход не запускается. |
| `commit_turn` внутри транзакции проверяет, что у `action_seq` ещё нет `turn.committed`; если есть, ничего не пишет и возвращает его `seq`. | Два повтора могут оба пройти проверку до первой записи. Защита на записи делает повтор идемпотентным по состоянию журнала, а замок хода сессии (Redis и `TurnSlots`) делает проверку и запись одним шагом. |
| В `TurnRequest.action` для повтора кладётся сам `RetryTurnAction`. | Контекст хода собирается из журнала по `action_seq`; объект действия сборка не читает. |
| Кадр `action_recorded` повтора несёт `seq` ввода без вердикта. | Вердикт ответа уже в журнале, сборка контекста читает его оттуда. |

Не сделано намеренно: повтор во время идущего хода той же сессии в том же процессе отменяет идущий ход (как любое новое действие, `TurnSlots`). Защита записи от отмены клиентом это задача 1.2.

Тесты: `backend/tests/session/test_retry_turn.py` (потерянная запись хода и повтор; повторный запрос с тем же и с другим ключом; гонка двух повторов; выбор последнего ввода; 404). Контрактный: `test_phase4_contracts.py`.
