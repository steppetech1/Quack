# Вложения к сообщению и PPTX

Жалоба: при загрузке документа выходит только «uploaded, duck is reading it», файл к сообщению не прикрепляется, а PPTX не читается.

## Что я нашёл (воспроизведено на живом стенде)

1. **Файл не прикреплялся по замыслу кода.** Скрепка в поле ввода только загружала файл в предмет и показывала всплывашку «uploaded». Файл не попадал в сообщение: ни плашки в поле, ни `material_ids` в сообщении (бэкенд такое поле уже принимал, интерфейс его не отправлял), ни следа под репликой. Учителю файл не передавался.
2. **«Утка читает» заканчивалась ничем.** Текст страниц извлекался и сохранялся в базу, но второй этап разбора (расстановка по графу знаний: темы, навыки, эмбеддинги) падал: приложение Modal `quack-embeddings` не найдено (`EmbeddingsUnavailable: App 'quack-embeddings' not found`). После пяти попыток материал помечался `failed`, а до учителя доходили только фрагменты, прошедшие граф, то есть ничего. Ваша первая загрузка в 10:46 UTC упала именно так.
3. **PPTX отклонялся на входе.** Принимались только PDF и изображения (`UPLOAD_REJECTED`, 415).

## Решения

**Статус «прочитан» (`read`).** Как только текст страниц сохранён, материал получает статус `read`; `parsed` остаётся для «всё, включая граф, готово». Если граф-часть позже падает, статус остаётся `read` (раньше становился `failed`), потому что текст уже на месте. `failed` теперь только если текст не получилось извлечь вовсе.

**Учитель видит вложение без графа.** Для файлов, прикреплённых к сообщениям сессии (последние три, до 12 000 знаков в сумме, настройки `material_attached_files` и `material_attached_chars`), учитель получает текст страниц прямо из базы, процитированный как данные. Файл ещё читается: учителю сказано, что он его пока не видит, и не придумывать содержимое. Файл не прочитан: сказано об этом прямо. Длинный файл обрезается с пометкой, остальное находит поиск по материалам. Текст файла остаётся данными (каждая строка с `> `), не инструкцией.

**Интерфейс.** Скрепка прикрепляет файлы к сообщению (до трёх): плашка в поле ввода с именем, состоянием («загружается», «читается», «готов», «не удалось прочитать») и крестиком. Кнопка «Отправить» ждёт, пока файл прочитается (учитель не получит файл, который не может увидеть). Файл без слов отправляется с заготовкой «Я прикрепил файл. Посмотри.» Под репликой ученика остаётся скрепка с именем файла, после перезагрузки страницы тоже. Для первого сообщения новой сессии (из поля на экране предмета) файлы передаются вместе с текстом.

**Имя файла.** Новая колонка `content.materials.title` (миграция `20261120000001`, nullable): имя, как его знает ученик (только последняя часть пути, без управляющих символов, до 120 знаков). Это метаданные показа, не факт модели ученика, поэтому в событие не добавлял (иначе ещё одно поле в строгой записи события и ещё одна ловушка раскатки).

**PPTX.**
- Приём: файл узнаётся по содержимому (zip, в котором есть `ppt/presentation.xml` и `[Content_Types].xml`), имя не смотрится. `.docx` и `.xlsx` тоже zip, но не принимаются. Маршрут фото холста по-прежнему принимает только свой вид.
- Чтение: в сервисе `compute` (там же, где разбор PDF, он изолирован и без сети) новая ручка `POST /v1/pptx/slides`. Только стандартная библиотека (zip и XML), новых зависимостей нет. Для каждого слайда: заголовок, весь остальной текст по порядку (абзацы, строки таблиц как `ячейка | ячейка`, текст формул Office Math, группы фигур), заметки докладчика. Порядок по списку слайдов презентации, а не по именам файлов. Картинки не читаются (картинок слайдов нет, образ страницы пустой).
- Защита: потолок числа частей архива (4000), размера одной части (8 МБ) и суммы после распаковки (64 МБ); части с `DOCTYPE` пропускаются; файл, который не презентация, это 422, и задача останавливается сразу, а не пять раз.
- Слайд становится страницей материала: заголовок, текст, затем «Notes: …».

**Попутно (по отчёту подагента о красном «Something broke»):** красное сообщение в вашей сессии вызвал мой перезапуск API в 10:55 UTC (пока браузер был открыт, прокси Next отвечал 500, ход при этом сохранился и учитель ответил). «Drawing a visualization» висело из-за таймаутов строителя демо: 6 из 8 вызовов упирались в лимит 60 с. Лимит роли `viz_builder` поднят до 180 с.

## Проверено

- **Живой стенд, настоящий Chrome:** прикрепил `dynamics.pptx` через скрепку → плашка «reading…» → «ready» (кнопка «Отправить» была заблокирована, пока читалось) → отправил вопрос «что на слайде про таблицу трения» → под репликой скрепка `dynamics.pptx` → учитель ответил по слайду 3: «wood on wood 0.35, steel on ice 0.03». Так же на ширине телефона (390 px); после перезагрузки имя файла под репликой на месте.
- **API:** `.pptx` принят и получил `title`; поддельный `.pptx` и неподходящий zip отклоняются с 415; PDF и PPTX из примеров доходят до статуса `read` за секунды (3 страницы и 4 слайда).
- **Тесты:** вычислительный сервис (разбор слайдов, порядок, таблицы, формулы, заметки, бомба, DTD, ручка 422): 7 прошло в контейнере; бэкенд на инфраструктуре: материалы, сессия, хранилище, агенты, задачи, холст, события, e2e и контракты 1087 прошло, затем после правки отказа 118 прошло (материалы, хранилище, снимок OpenAPI). `ruff`, `pyright` (backend), `tsc`, `eslint` без ошибок.

## Что не решено и что нужно от тебя

- **Приложение Modal `quack-embeddings` не развёрнуто в вашем аккаунте.** Пока так, расстановка файла по графу знаний (темы и навыки из лекции, `chunk.indexed`, поиск по материалам, хаб «из материала») не работает: задача `material.parse` второго этапа крутится и падает, на плашке остаётся «Reading the material». Текст файла при этом доступен учителю. Развернуть: `modal deploy modal/embeddings.py` (действие владельца по ТЗ Ф4 §1.3; это облачный ресурс в вашем аккаунте Modal, сам я его не разворачивал).
- Сканы PDF без текстового слоя читаются моделью постранично (до лимита страниц): это дольше, кнопка «Отправить» ждёт.
- Слайды без текста (одни картинки, схемы) дают пустые страницы: картинки слайдов не читаются.
- Раскатка: применить миграцию `20261120000001` до кода API; новый код `compute` с ручкой `/v1/pptx/slides` до `workers`.
