# Переход на подписку ChatGPT как источник моделей

Nov 16, 2026 · черновик по обзору кода и документации OpenAI

## 0. Итог

Ученик входит через ChatGPT и разрешает Quack тратить лимит своей подписки. Ход учителя идёт на его подписке, наш харнесс не меняется. Meta API остаётся бесплатным слоем, пока есть бюджет, и источником для ролей, которые подписка не покрывает.

Память, проектор, проверка ответов, очередь задач и граф хода не меняются. Меняются шлюз моделей, учёт расхода, вход и экран настроек.

Главное препятствие в коде одно: на процесс создаётся один провайдер с одним ключом (`api/resources.py:80`, `runtime/__init__.py:57`, `cli.py:222`). Подписочный путь требует выбирать учётные данные на каждый вызов по ученику.

Главная развилка тоже одна: кто держит токен ученика и вызывает модель — наш сервер или приложение на его устройстве (§3). Сегодня без заявки в OpenAI открыт только второй путь. Поэтому работы разделены на общие для обоих вариантов (§2) и зависящие от выбора (§3).

Основа документа: модули `llm/`, `auth/`, `config.py` и сборка процессов прочитаны; остальной код просмотрен поиском по привязкам к Meta.

## 1. Что известно про путь OpenAI

Проверено по документации OpenAI (`developers.openai.com/siwc/token-sharing-open-source`):

- Вызов: `POST https://api.openai.com/v1/responses` с токеном ученика. Обязательны `store=false` и `stream=true`.
- Свои инструменты и картинки на входе поддерживаются. Инструменты группируются в пространства имён или передаются через `additional_tools`.
- Не принимаются поля: `max_output_tokens`, `temperature`, `previous_response_id`, `metadata`, `truncation`, `user`. Сообщения с ролью `system` отклоняются, вместо них поле `instructions`.
- Не поддерживаются: расшифровка голоса, генерация картинок, Files API, встроенные инструменты OpenAI.
- Список моделей берётся запросом `GET /v1/models` с тем же токеном.
- Токен доступа живёт час, токен обновления 30 дней и меняется при каждом обновлении.
- Перед вызовом надо проверить, что выдано право `chatgpt.tokens.use.direct`.
- Ошибки: `subscription_sharing_usage_limit_exceeded` (429) и `subscription_sharing_user_not_eligible` (403). Лимит может быть отдельным на приложение.
- Самостоятельная регистрация открыта открытым и локально запускаемым приложениям: общий идентификатор клиента `dynamic_agent_client`, без секрета. Платным и размещённым на сервере нужна заявка.

Не подтверждено:

- поддержка строгих схем `text.format: json_schema`;
- подходит ли наш текущий формат описания инструментов;
- как устроен вход для локального приложения (адрес возврата, PKCE) и похож ли он на наш вход через Google;
- размер лимита Plus и Pro, доступ на бесплатном тарифе;
- принимается ли `prompt_cache_key`, приходят ли заголовки `x-ratelimit-*`;
- можно ли вызывать модель без участия ученика (фоновые задачи);
- можно ли брать с ученика деньги сверх подписки;
- считается ли локальным приложение, где модель вызывает наш сервер.

## 2. Общие работы (нужны при любом варианте)

### 2.1 Шлюз: источник оплаты на каждый вызов

Сейчас `LLMGateway` получает один `ResponsesClient` при старте.

- Ввести источник оплаты: подписка ученика, наш пул (Meta), позже ключ ученика.
- Шлюз выбирает источник по ученику и роли. `learner_id` уже передаётся в текстовые и медиа-вызовы, этого достаточно.
- **Источник фиксируется на весь ход.** Цикл инструментов переносит между шагами зашифрованные элементы рассуждения (`llm/streaming.py:323`), а они привязаны к поставщику. Если лимит подписки кончился посреди хода, ход начинается заново на пуле без перенесённых элементов. Между ходами эти элементы не переносятся, так что соседние ходы могут идти на разных источниках.
- **Задачи без ученика** (периодические, `jobs/periodic_p4.py`) идут только на пуле.
- Шов `LLMProvider` (`llm/provider.py`) оставить: через него подключается и вариант с вызовом на устройстве.

### 2.2 Тело запроса

Все отличия собраны в `ResponsesClient._body` (`llm/responses_client.py:195`) и `stream_structured` (`:422`).

| Что | Сейчас | На подписке |
| :-- | :-- | :-- |
| Нестриминговые вызовы | `complete_structured` без `stream` | только `stream=true`: собирать ответ из потока |
| `max_output_tokens` | шлётся всегда | убрать; обрыв ловить по `status: incomplete` |
| Удвоение лимита при обрыве | `tool_loop.doubled` | не работает, нужен другой повтор |
| Строгая схема | основа всех ролей | проверить на спайке; без неё переход невозможен |
| Описание инструментов | плоский список, `tool_choice: auto` | проверить формат на спайке; от него зависят инструменты памяти учителя |
| `prompt_cache_key` | шлётся | проверить на спайке |
| Сообщения | только роль `user` | подходит; стабильную часть можно перенести в `instructions` |
| `phase: commentary` | фильтруется | проверить, что OpenAI размечает так же |

### 2.3 Лимиты и отказы

Сейчас ответ 429 ставит флаг давления на модель для всех учеников (`gateway._rate_limited`, `llm/pressure.py`), предохранитель считается по модели.

- Отказ по лимиту подписки касается одного ученика. Он не должен ставить общий флаг и открывать предохранитель.
- Новые ошибки в `llm/errors.py`: лимит подписки исчерпан, тариф не подходит, право отозвано. Каждая переводит ученика на пул или даёт понятное сообщение.
- Семафоры параллельности заданы по именам моделей Meta (`config.py:431`). Для моделей OpenAI нужны свои значения.

### 2.4 Роли и модели

Таблица ролей в `config.py:188` привязана к `muse-wonder-1.0` и `muse-spark-1.3`.

- Заменить имена моделей на классы «сильная» и «быстрая», которые каждый источник переводит в свою модель. Для подписки модель выбирается из списка, доступного ученику.
- Предлагаемое деление:

| Роли | Источник |
| :-- | :-- |
| `teacher`, `verdict_free`, `verdict_proof`, `canvas_diagnoser`, `recognizer` | подписка ученика, при отказе пул |
| `extractor`, `analyst`, `builder`, `material_parser`, генерация и проверка задач, артефакты | пул, пока не ясно, разрешены ли фоновые вызовы на подписке |
| `voice`, `segmenter`, `illustrator` | только Meta: подписка это не покрывает |
| эмбеддинги (Modal) | без изменений |

- Когда Meta закончится, голос, выделение рисунков на фото и иллюстрации отключаются или требуют другого поставщика.

### 2.5 Учёт и бюджеты

- `ops.llm_usage`: добавить источник оплаты. Вызовы на подписке пишутся с токенами и стоимостью 0 для нас.
- Режим `judges_only` и признак «судья Meta» — остаток хакатона. Он живёт в `llm/access.py`, `session/router.py:165–242`, `jobs/queue_p4.py`, `jobs/executor_p4.py` и в настройках на фронтенде. Заменить правилом: пул исчерпан — модели доступны только с подпиской.
- Бюджеты в долларах и таблица цен `llm_prices` применяются только к вызовам из пула.

### 2.6 Промпты и качество

- У учеников будут разные модели в зависимости от тарифа. Решить, какой минимум поддерживается.

## 3. Развилка: кто держит токен

### Вариант А. Токен на нашем сервере

Доступен только после одобрения заявки OpenAI.

- Вход через ChatGPT рядом с входом через Google и почту (`auth/router.py`), маршруты во `frontend/app/api/auth/`.
- Таблица токенов ученика: токен обновления в зашифрованном виде, срок, права, состояние. Миграция и секрет шифрования.
- Обновление токена в одном месте под блокировкой в Redis: токен обновления одноразовый, а модель вызывают два процесса (`api` и `workers`).
- Удаление аккаунта (`quack/deletion`) стирает токены, отключение в настройках отзывает их.
- `ResponsesClient` принимает токен на вызов, а не только при создании.
- Фоновые роли на подписке возможны, если OpenAI это разрешает.

### Вариант Б. Токен на устройстве ученика

Открыт сегодня для открытого локального приложения. Требует десктоп-оболочки.

- Вход и хранение токена — в приложении, сервер токена не видит.
- Ход учителя делится надвое: сервер собирает запрос и исполняет инструменты, приложение вызывает модель и возвращает поток событий. Это новая реализация `LLMProvider` и новый канал между сервером и приложением.
- Защитные правила хода (буфер спойлеров, проверка пререквизитов) остаются на сервере, но ответ модели проходит через устройство ученика. Проверить, что это не открывает обход.
- Фоновые роли на подписке невозможны, когда приложение закрыто: они остаются на пуле.
- Веб-версия работает только на пуле.
- Не ясно, признаёт ли OpenAI такую схему локальной.

## 4. Спайк до начала работ

Локальный скрипт с токеном собственной подписки, без изменений в продукте.

1. Вход локального приложения: как выглядит и что возвращает.
2. Строгая схема `text.format: json_schema` вместе с инструментами и стримингом.
3. Формат описания инструментов и цикл с несколькими вызовами.
4. Перенос элементов `reasoning` с `encrypted_content` между шагами цикла.
5. Поведение без `max_output_tokens`: как выглядит обрыв, сколько уходит на рассуждение.
6. Картинка на входе для распознавания рукописи.
7. `prompt_cache_key`, заголовки лимитов, формат ответа 429.
8. Какие модели видит Plus и сколько ходов учителя (около 30 тыс. токенов) помещается в лимит.
9. Время до первого текста учителя.

Пункты 2–4 решают, возможен ли переход вообще. Пункт 8 решает, хватит ли подписки на реальную учёбу.
