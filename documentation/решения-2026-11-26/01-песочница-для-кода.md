# Песочница для кода в чате

Решение владельца 2026-11-26. Задачу с кодом пишет сам учитель прямо в ходе, редактор открывается сразу. Ученик не ждёт, пока задачу сгенерируют, а потом проверят тестами.

## Что было

Учитель (`teacher@4`) заказывал задачу агенту `task_generation` с языком. Генератор писал эталон и входы тестов, раннер считал ответы, независимый решатель проверял задачу. Только после этого задача появлялась в чате, следующим ходом, через минуту и больше.

## Что изменено

**1. Учитель `teacher@5` пишет элемент `code_sandbox`** (`backend/quack/session/elements.py`, `backend/quack/prompts/teacher/v5.md`). Поля элемента: режим (`inline_patch` или `full_problem`), язык (`python`, `sql`), условие, заготовка, `entry_point`, пресет БД, один пример (`sample_args_json`, `sample_expected_json`) и режим сравнения (`exact`, `unordered`, `float_approx` с `epsilon`). Разметка задачи лежит в `tasks`, как у любой задачи, с типом ответа `code`. `teacher@4` оставлен для отката настройкой роли.

**2. Задача создаётся в том же ходе** (`backend/quack/session/turn_commit.py`, `backend/quack/practice/code_sandbox.py`). Первый тест задачи — пример учителя. Плохой элемент (не JSON, не идентификатор, неизвестный пресет) отбрасывается вместе с задачей, ход остаётся. Повторного вызова исправления на это нет: оно чинит разметку, а не элемент.

**3. Скрытые тесты `full_problem` собираются в фоне** (`backend/quack/practice/code_hidden.py`). Сборку запускает задача `task.check`, которая уже ставится по `turn.committed` для задач хода. Новой строки диспетчера нет. Роль `code_test_builder@1` пишет эталон и до 4 входов с короткими именами кейсов, ожидаемых ответов она не пишет. Дальше двойная проверка в раннере: эталон сначала идёт на примере учителя, и при ошибке или несовпадении он сломан. Если пример пройден, ожидаемые ответы на остальных входах — то, что вернул эталон. При провале делается одна повторная попытка (`code_build_attempts = 2`), причина провала передаётся модели. Если провал повторился, получается `build = failed`: задача тихо остаётся на примере и ревью учителя. Для кода задач `task_checker` не вызывается.

**4. Гонки.** Результат сборщика пишется условным `UPDATE … WHERE build = 'pending'` по `task_id`, поэтому повтор или опоздавший ответ ничего не перетирает. Панель редактора живёт, пока открыта её задача (`key = task_id`), и ответ опроса по другой задаче отбрасывает.

**5. SQL.** Пресеты `shop` и `university` (`backend/quack/practice/sql_presets/`) копируются в схему и данные задачи. Раннер и раньше пускал запрос ученика только на чтение. У SQL нет скрытых тестов: в песочнице это всегда `inline_patch`. Имена столбцов не сравниваются, только значения. Порядок строк учитывается только при `exact`. Плоский список в примере читается как один столбец.

**6. Что видит ученик.** «Запустить» никогда не заблокирован: он гоняет все тесты, какие есть сейчас (пример и, когда они готовы, скрытые). Пока тесты в работе, показывается «Базовый пример пройден, дополнительные тесты ещё готовятся…». По скрытому тесту ученик видит имя кейса, вход и свой вывод или ошибку, но не ожидаемый ответ (`CodeTestView.hidden_view`). «Отправить учителю» доступна всегда: пишутся `answer.submitted` и `verdict.recorded`, затем фронт запускает `retry_turn`, и следующий ход учителя и есть ревью. В `full_problem`, когда все тесты пройдены, код уходит сам через 4 секунды, а кнопка «Отмена» это останавливает.

**7. Ожидаемый ответ скрытого теста в промпте учителя.** В `detail` вердикта у именованного скрытого теста теперь есть имя кейса и ожидаемый ответ, так учитель видит их при ревью. Событие на клиент не уходит. Это отход от прежнего правила Т-§6.10 («скрытый тест — только статус»): так требует ТЗ песочницы. Старые задачи (скрытые тесты без имён) показываются и пишутся как раньше.

**8. Лимиты и состояние.** `stdout`/`stderr` обрезаются до 2000 символов (`code_output_chars`). Время одного теста Python в раннере — 3 с (`py_wall_s`, было 5 с). Код ученика и статусы последнего запуска хранятся в `content.tasks.code_draft` (расширяющая миграция `20261126000001`). Черновик сохраняется при запуске и через `PUT /v1/tasks/{id}/code/draft` через 1,5 с после ввода.

## Что не сделано

- JS и C++: контракт задачи их не закрывает (язык, `entry_point`, режим сравнения), но в раннере нет харнессов, а в образе нет node и g++. Это следующий шаг.
- Старый путь `code_task_generator` / `code_task_checker` в коде остался: по нему показываются старые задачи. `teacher@5` его не вызывает.
