# Структура предмета: темы, корневые навыки и граф без лишнего дробления

## Проблема

На первых разборах материалов и сессиях проявились пять перекосов структуры предмета:

1. **Лишнее дробление навыков и размытые темы.** Разбор кусков материала (`teaches`/`uses`) создавал мелкие навыки под каждый абзац, а у тем не было явного описания и единого корневого критерия.
2. **Лишние хабы материалов.** Каждый загруженный файл плодил отдельный хаб «из материала» и тормозил обработку ожиданием порядка загрузки.
3. **Осиротевшие временные навыки.** При разметке хода и задач в сессии новые навыки без совпавшего `topic_hint` оставались вне темы или не знали других навыков темы, а также порождали дубли.
4. **Навыки-инструменты (дополнение #1) и пустые рождения (дополнение #2).** Модели создавали отдельные навыки на инструмент или способ решения (например, «Excel»), а временные навыки из непроработанных веток диалога оставались в графе с 0 свидетельств и 0 показов после завершения сессии.
5. **Шумные связи `REQUIRES`.** Уверенные и гипотетические связи от модели шли с одинаковой силой (`0.65` и без визуального различия на графе), а повторные/транзитивные/встречные рёбра засоряли карту тем.

## Решение

1. **Одна тема — один корневой навык (`core = true`).**
   - У `Topic` появилось поле `description`, у `Skill` — `core`, `definition`, `exemplar`, `kind` (`summary` хранит `definition`, а не сырой текст куска).
   - Каждая новая тема создаётся сразу с одним `core = true` навыком (проверяемым одной задачей); корневой навык нельзя удалить через `skill.deleted`.
   - Дополнительные навыки в теме появляются только из реальной работы ученика (ход учителя, генерация/разметка задач, извлечение), когда отдельная проверка меняет дальнейший шаг.

2. **Разбор материалов с оглавлением (`material_parser@2`) без хаба материала.**
   - Режим `parse` размечает куски (`section`, `notation`, `builds_on`, `deadlines`, `seminar_tasks`) без создания навыков по кускам.
   - Режим `toc` (батчами по `material_toc_max_chunks = 40`) строит оглавление кандидатов тем (`name`, `description`, `core_skill_name`, `builds_on`).
   - Отдельный хаб материала не создаётся (хабы остаются только `request`, `deadline`/силлабус, `domain_all` и ПОЗЖЕ `suggested`); ожидание порядка загрузки убрано, `chunk.indexed` привязывается `TEACHES` к корневому навыку темы.

3. **Единый Structure writer (`builder@2`, режим `Structure`).**
   - Обрабатывает кандидатов тем и временные навыки последовательными батчами (`structure_batch_size = 15`) с `append_unwritten`, видя до `structure_full_list_max_topics = 80` тем домена и похожие навыки из других тем.
   - Фильтрует рёбра `REQUIRES`: отбрасывает `score < 0.3`, встречные пары в одном батче, обратные к существующим и транзитивно выводимые.

4. **Горячий путь и разметка задач (`teacher@4`, `task_generator@2`).**
   - Код вычисляет `focus_topic_id` при `turn.committed` (и `topic_id` в `task.created`), чтобы новый временный навык сразу крепился к фокусной теме; `NewSkill` несёт `reason`.
   - В `task_generator@2` для сгенерированных и семинарных задач передаются все навыки темы (`topic_skill_ids`).

5. **Инструменты как контекст (дополнение #1) и очистка пустых рождений (дополнение #2).**
   - Инструмент/способ решения передаётся в `TESTS.context` и сохраняется в `Evidence.context`, не создавая новый навык.
   - После `session.ended` временные навыки этой сессии с 0 свидетельств и 0 показов объединяются с корневым навыком своей темы (`skill.merged`) либо удаляются (`skill.deleted`, `reason = "empty_session_birth"`), если темы нет.

6. **Уверенность связей `REQUIRES` и визуализация на графе.**
   - Начальная уверенность для `model` снижена до `0.5` (`material = 0.85`). Мульти-источниковые рёбра детерминированно хранят `max(confidence)` и список `origins`.
   - `TopicRequires` в API чтения графа возвращает `confidence = max(coalesce(r.confidence, 1.0))`; на фронтенде (`LayeredGraph`) прозрачность и толщина рёбер между темами зависят от `confidence` (`<= 0.5`: 0.35 / 1.0px, `<= 0.85`: 0.8 / 1.4px, `>= 1.0`: 1.0 / 1.8px).
   - Для контроля качества добавлена команда `python -m quack.cli ops structure-report`.

## Критерии проверки

- 0 пустых тем и 0 тем без `core = true` навыка в графе домена.
- При разборе материалов не создаётся ни один не-core навык и не создаётся хаб `kind = "material"` (силлабус-дедлайны сохранены).
- Временные навыки без свидетельств и показов убираются после `session.ended`.
- Инструменты фиксируются в `Evidence.context`, не создавая навыков.
- `TopicRequires.confidence` отражается в OpenAPI, `schema.d.ts` и визуальном весе/прозрачности рёбер на графе; `ops structure-report` и автотесты проходят.
