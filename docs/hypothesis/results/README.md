# results — проверка после реализации

Сюда кладём результаты проверки гипотез, когда реализация готова. Одна папка на проверку: `YYYY-MM-DD-<коротко>/`.

## Что кладём

- **Отчёты как есть.** Например, вывод `uv run python -m quack.cli ops structure-report --learner <id> --domain <id>` ([спека](../specs/2026-11-25-structure-building.md), раздел 4.8).
- **Условия:**
  - коммит;
  - модели и провайдер из `ops.llm_usage`;
  - какие файлы и в каком порядке загружены;
  - id ученика и предметов.
- **Снимки журнала** теми же запросами, что в наблюдении, с которым сравниваем: `observations/.../raw/queries.sql`. Так обе стороны сравнения считаются одинаково.
- **Скриншоты графа** для сравнения рядом.
- **README** со сравнением по метрикам карточек:
  - число из отчёта;
  - порог из карточки;
  - вывод `confirmed` / `refuted` / «мало данных».

## Первая ожидаемая проверка

Side-by-side по [наблюдению 2026-11-25](../observations/2026-11-25-statistics-seminars/README.md): те же 7 листов семинаров по статистике, загруженные в новый предмет на новой версии.

**Смешивающий фактор.** Базовая линия снята на моделях Meta: `muse-spark-1.3` и `muse-wonder-1.0`. Если новая версия пойдёт на моделях OpenAI, разница будет и от модели, и от кода. Чтобы разделить, нужен хотя бы один прогон новой версии на тех же моделях Meta или старой версии на OpenAI.
