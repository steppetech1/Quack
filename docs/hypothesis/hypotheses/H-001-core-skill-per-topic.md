## Утверждение

Тема создаётся сразу с одним центральным навыком: главным умением темы, названным действием. Других навыков при создании нет; они появляются только из реальной работы ученика ([H-006](H-006-focus-topic-for-new-skills.md), [H-003](H-003-task-markup-closed-choice.md)).

Критерий темы для любого источника: у неё одно центральное умение. Если одно назвать не получается — это две темы.

## Почему (опыт)

- **Пустые темы ломают граф и экран.** Две темы без навыков, рядом двойники с навыками; третий двойник гигиена слила ([raw/18](../observations/2026-11-25-statistics-seminars/raw/18-topics-final-counts.txt), [скриншот 03](../observations/2026-11-25-statistics-seminars/screenshots/03-empty-twin-topic-clt.png)).
- **Жадное создание навыков раздувает предмет:**
  - база (одна загрузка): 124 навыка на 14 тем — 90 из материала и 34 временных от разметки задач ([raw/16](../observations/2026-11-25-statistics-seminars/raw/16-baseline-first-upload.txt));
  - после двух загрузок в одной теме до 29 навыков ([raw/18](../observations/2026-11-25-statistics-seminars/raw/18-topics-final-counts.txt));
  - дубли и варианты инструмента.
- **Связям нужен навык.** Связи тем выводятся из `REQUIRES` между навыками. Тема без навыков не может иметь связей.
  - Ассистент сам указал на эту дыру в своей идее «ленивого» создания ([R-003](R-003-pure-lazy-skills.md)).
  - Владелец спросил о том же: «как тогда связи будут строиться если в таком случае изначально тема пустая» (19:12).
- **Без навыков темы молча ломаются другие части** (вывод модели, [отчёт критика](../observations/2026-11-25-statistics-seminars/reviews/critic-report.md), раздел 2, с местами в коде):
  - поиск материалов для учителя;
  - готовность темы (`topic_fold`);
  - «Сегодня» (`review/today.py`).

## Как проверяем

Отчёт `structure-report` ([спека 4.8](../specs/2026-11-25-structure-building.md)) и запросы [queries.sql](../observations/2026-11-25-statistics-seminars/raw/queries.sql) на новой версии.

- **Метрика 1 — после разбора:**
  - пустые темы;
  - темы без центрального навыка;
  - число навыков против числа тем.
  - **Подтверждение:** 0 и 0, навыков = тем.
- **Метрика 2 — после нескольких сессий:**
  - распределение навыков на тему;
  - доля новых навыков, набравших хотя бы 3 свидетельства за 14 дней.
  - Это проверка, что навыки рождаются по делу.
- **Метрика 3 — доля задач с `new_skill`.** Базовая — 22 из 48 ([raw/16](../observations/2026-11-25-statistics-seminars/raw/16-baseline-first-upload.txt)).
- **Опровержение:**
  - центральный навык слишком крупный: задачи и учитель всё равно массово уходят в `new_skill`, доля не падает заметно ниже базовой;
  - или владелец видит, что состояние центрального навыка не отражает знание темы. Пример: «решаешь сам» по теме, где ученик умеет одну часть из нескольких.
- **Чем можно спутать:**
  - смена моделей Meta → OpenAI;
  - набор из одних листов задач без теории — не типичный предмет.
  - Нужна хотя бы одна сессия без файлов ([спека 7.3](../specs/2026-11-25-structure-building.md)).

## Стартовые значения

Порог «3 свидетельства за 14 дней» в отчёте выбрал ассистент.

## Риски и что известно заранее

- **Инварианты при изменении тем** ([спека 4.1](../specs/2026-11-25-structure-building.md)):
  - при слиянии тем сливаются их центральные навыки;
  - при делении каждая часть получает свой;
  - центральный навык не удаляется отдельно от темы.
- **Одно число состояния на большую тему** может завышать готовность. Это та же проблема, что критик нашёл в `topic_fold`, только в другой форме.
- **Исследования прямо этого не проверяли.** Исследования зерна навыков есть в [обсуждении](../observations/2026-11-25-statistics-seminars/discussion.md), но это вывод модели. Центральный навык — гипотеза продукта, не результат статьи.
