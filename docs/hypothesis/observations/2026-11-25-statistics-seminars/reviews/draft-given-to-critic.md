## 2. Как сделано сейчас и почему

Конвейер материала (backend/quack/materials/parse.py, ops/material_parse.py, agents/reconcile.py):
1. Файл режется на куски по 1500 знаков; material_parser (пачками, параллельно, пачки не видят друг друга) пишет на кусок: topic (свободный текст), teaches[], uses[] (свободные имена, до 6), задачи семинара.
2. _subjects: каждое имя из teaches и uses → кандидат-навык; тема навыка — тема куска, только если кусок учит, иначе название файла; summary навыка = первые 300 знаков сырого текста куска (по нему же строится вектор навыка).
3. reconcile_domain: builder получает кандидатов пачками по candidate_k=15 с найденными по вектору кандидатами-узлами, решает link/create/suggest_merge; для нового навыка сам называет тему (topic_hint: метка или новое имя) — она побеждает тему из разметки.
4. REQUIRES: единственный источник — «кусок учит X и использует Y» → X→Y, и только если X и Y решены в одном вызове builder. Builder о связях не спрашивают.
5. Хаб «из материала» для каждого файла (темы навыков, которым учит файл, иначе темы кусков).
6. graph.hygiene (agents/hygiene.py) потом сливает дубли (только временные навыки сливаются без ученика) и в режиме Topics перекладывает навыки по темам (86 событий skill.placed в этом предмете).
7. Связи тем на графе не хранятся: выводятся при чтении из REQUIRES навыков (neo4j_reader.topic_requires).

Из сессий: учитель размечает ход меткой навыка или описанием нового {name, topic_hint} → временный навык (provisional), временная тема при несовпадении; извлекатель аналогично; сверка временных — фоном (§4.4).

Замысел документа (почему так): граф растёт из любых источников событиями; модели не видят id (короткие метки, закрытый выбор); кандидатов готовит код векторами, модель только выбирает — один вызов (§4.3); одна домашняя тема у навыка; связи тем выводятся из навыков, чтобы не было двух расходящихся графов связей (§3.4.5); зерно навыка — проверяется одной задачей, «по умолчанию один навык на тему», ориентир 1–6 (§4.1).

Где замысел ломается на практике:
- Навыки создаются жадно из любого упоминания (каждое uses), а не по нужде измерения → инфляция и дубли.
- Описание навыка = сырой текст куска → векторы навыков одного куска почти одинаковы, поиск кандидатов и дублей слепнет.
- Тему решают три несогласованных источника (разметка куска, название файла, topic_hint builder, потом hygiene) → пустые темы-оболочки.
- У «нужно до» нет нормального источника: побочный признак «учит+использует в одном куске», только внутри одного вызова; листы задач не дают ничего; между файлами — никогда. При этом раскладка главного экрана («снизу основы», П-3.2) держится на этих связях.
- Пачки разметки не видят друг друга → одно и то же называется по-разному даже внутри файла.

## 3. Мои предположения в ходе обсуждения (аудит)

- «Картограф видит всю карту и правит её» — разумно для малых предметов (десятки–сотни тем), но не проверено по качеству и цене.
- «Порядок курса как сигнал связей» — отвергнуто пользователем: система не должна опираться на материалы и нумерацию.
- «Лимит 1–6 бессмыслен» — частично: это эвристика цены измерения (каждый навык требует попыток и задач). Мягкий ориентир, не правило.
- «Ленивое создание навыков» — верное направление для материалов, но требует, чтобы связи тем существовали без навыков.
- «Эло вместо свёртки» — ошибка: смешивает понимание и забывание, теряет знакомство, границу цели и объяснимость. Вне рамок этой переделки.
- «Тема = крупный навык» — гипотеза пользователя, не принята как основа.
- «Связи тем хранятся отдельно, с источниками, уверенность считает код» — противоречит решению §3.4.5 (одна правда — связи навыков). Нужна защита от двух расходящихся графов.
- «Модель по знанию предмета ставит связи тем с уверенностью 0.5» — НЕ проверено: насколько LLM точны в определении «нужно до» между понятиями.
- Цены: объёмы токенов сняты с Meta-моделей на стенде, у OpenAI рассуждение может быть другим; фоновые роли пойдут из нашего пула (подписка ученика их, возможно, не покрывает — не подтверждено OpenAI).

## 4. Предлагаемая архитектура (только построение структуры; свёртка состояния не меняется)

### 4.1 Тема — основная единица структуры, создаётся сразу
- Источники: раздел материала, ход учителя (новая тема в разметке), просьба ученика.
- У темы: имя, описание 1–3 фразы (генерируется при создании), черновой список граней (имена будущих навыков, просто текст), источники.
- Зерно темы: «одна главная идея, которую можно изучать одной сессией». Если граней много и они разнородны — предложение разделить тему (существующий режим Split).
- Решение «новая тема или существующая» принимает один писатель структуры (п. 4.4) в закрытом выборе против ВСЕГО списка тем предмета (имена + описания); темы не создаются из названий файлов и не переизобретаются сборщиком навыков.

### 4.2 Навык — создаётся лениво, по нужде измерения
- Узел навыка появляется только когда нужно что-то измерить или чему-то научить: учитель размечает объяснение/задачу, задачу выдают ученику (TESTS), извлекатель относит ответ, ученик просит.
- Материал навыков не создаёт: только грани темы (текст) и задачи семинара в банке темы с пометкой грани, без TESTS до первой выдачи.
- Сверка нового навыка: против навыков своей темы и её граней (закрытый список, единицы–десятки) + ближайших навыков других тем по вектору (против дублей между темами: если умение уже живёт в другой теме — это связь «нужно до», а не новый навык).
- У навыка: name (действие), definition (одна фраза «умеет…», что входит/не входит), exemplar (1 образец задачи), kind (факт/понятие/процедура/принцип); вектор по name+definition. Сырой текст куска на навыке не хранится.
- Варианты инструмента (Excel и т.п.) — контекст задачи, не навык. Уровни 1–6 — уровни навыка, не отдельные навыки. Метанавыки — профиль ученика.
- Слияние: дубль при сверке; «всегда проверяются вместе». Деления навыка нет; детализация — новыми навыками.

### 4.3 Связи «нужно до»
- Два слоя с разным назначением, без двух расходящихся правд:
  - REQUIRES между навыками (как сейчас) — единственный источник для модели ученика: косвенные свидетельства, правило «опоры». Контракт не меняется.
  - REQUIRES между темами — хранится, служит только навигации: раскладка графа, порядок плана, мягкое предупреждение. Никогда не порождает свидетельств.
- Связь тем на графе = объединение: хранимые связи тем + выведенные из связей навыков (как сейчас). Если появилась связь навыков между двумя темами — это доп. источник для связи тем.
- Источники связи тем и уверенность (считает код): знание предмета моделью (база); прямо в материале с цитатой (выше); подтверждена связью навыков или ошибками ученика (выше); ученик сказал (максимум / удаление).
- Ставит их тот же писатель структуры при появлении темы: модель видит новую тему и все темы предмета (имена+описания), отвечает метками «на что опирается / что опирается на неё» + тип источника + цитата. Код: нет встречных, нет циклов (или сжатие компонент для порядка), транзитивное упрощение при отображении.

### 4.4 Один писатель структуры на предмет
- Фоновая задача под lock domain:{id}, с задержкой-«дребезгом» (собирает всё новое за N секунд): размещение новых тем (закрытый выбор против списка тем), связи новых тем, сверка временных навыков, слияния дублей. Заменяет: reconcile_domain для материалов, режим Topics гигиены, отдельные гонки за тему.
- Модель только выбирает и описывает; код пишет события; ответ модели сохраняется событием до применения, повтор применяет сохранённое (без IdempotencyConflict).

### 4.5 Материал
- Разбор: вид материала, разделы → кандидаты тем (имя, описание, грани), прямые утверждения «нужно до» с цитатой, задачи с привязкой к разделу. Без навыков, без хабов, без порядка файлов.

### 4.6 Хабы
- Только по прямой просьбе ученика (решение пользователя 2026-11-25). Из материалов — нет.

### 4.7 Цена (OpenAI, Standard, за 1M: gpt-6-luna $0.10/$0.50; gpt-6.1-terra $1/$5)
- Разбор материала: как сейчас по числу вызовов разметки (около 5–8 на лист), но без вызовов сборщика на каждые 15 имён.
- Писатель структуры: ~3k вход / ~1k выход на пачку → Luna ≈ $0.001, Terra ≈ $0.01.
- Сверка навыка: ≈ $0.0002 (Luna) на навык пачкой.
- Главная статья — генерация задач (~$0.004 Luna / ~$0.04 Terra на задачу); ленивое создание навыков её сокращает.

### 4.8 Проверка до внедрения
- Эталонные карты вручную: 7 семинаров статистики, 6 лекций статистики (QA-набор), 1–2 сессии без файлов.
- Метрики: пустых тем 0; доля дублей тем/навыков; точность/полнота связей тем против эталона; стабильность (тот же вход дважды); число навыков на тему после N сессий; стоимость.
